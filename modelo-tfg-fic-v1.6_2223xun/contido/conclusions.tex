\chapter{Conclusiones}
\label{chap:conclusions}

\lettrine{E}{l} trabajo se consolida en torno a una idea principal: construir un sistema de captura inercial capaz de operar con más de una plataforma de adquisición dentro de un mismo flujo de trabajo.

\section{Conclusiones principales}

\begin{itemize}
  \item Android resulta una base viable para captura, gestión de sesiones y operación de campo en fases tempranas del sistema.
  \item La separación funcional entre adquisición, comunicación, persistencia y visualización facilita mantenimiento e integración progresiva.
  \item La incorporación de un nodo ESP32 aporta una ruta realista para adquisición dedicada y para validar la interoperabilidad entre plataformas.
  \item El estado actual permite un flujo funcional local extremo a extremo y deja preparada la evolución hacia operación remota.
\end{itemize}

\section{Conclusión metodológica}

La principal conclusión metodológica del TFG es que, en un proyecto de este alcance, resulta más sólido cerrar primero una arquitectura operativa por capas que comprometer desde el inicio una infraestructura definitiva.

Este criterio ha permitido:

\begin{itemize}
  \item reducir riesgo técnico por integración progresiva;
  \item mantener trazabilidad entre decisiones y resultados;
  \item diferenciar claramente funcionalidades implementadas frente a líneas de evolución.
\end{itemize}

\section{Implicaciones prácticas}

Desde el punto de vista de ingeniería, la solución propuesta permite:

\begin{itemize}
  \item reutilizar la misma lógica de operación con distintos nodos de adquisición;
  \item introducir backend remoto sin rediseñar captura ni interfaz;
  \item evaluar tecnologías de comunicación por evidencia, no por compromiso previo.
\end{itemize}

\section{Aportaciones}

Las aportaciones del trabajo en su estado actual son:

\begin{itemize}
  \item definición de una base ciberfísica para captura inercial sobre plataformas heterogéneas;
  \item implementación de modo móvil operativo con gestión de sesiones;
  \item integración funcional Android-ESP32 para control y descarga de capturas;
  \item formalización de contratos de sesión, control y explotación;
  \item marco de validación orientado a interoperabilidad y operación.
\end{itemize}

\section{Trabajo futuro}

Las líneas de continuidad más relevantes son:

\begin{itemize}
  \item integrar una primera capa backend para sincronización de sesiones y estado;
  \item ejecutar campaña de validación comparativa completa con protocolo homogéneo;
  \item mejorar trazabilidad automática (versionado de configuración y registro de incidencias);
  \item evaluar alternativas de comunicación externa si aportan mejoras medibles en operación;
  \item reforzar automatización de pruebas de integración entre app y nodo embebido.
\end{itemize}

\subsection{Línea prioritaria inmediata}

La prioridad inmediata es consolidar una primera versión funcional de capa backend y cerrar la validación de integración extremo a extremo sobre esa base.
